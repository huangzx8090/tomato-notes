# 本地资料保存与统一

## 日常使用

计时状态、专注轮次、App 时长、设置、待办、便签及成果记录保存在 `~/Library/Application Support/TomatoNotes/data.json`。成果图片保存在旁边的 `Attachments/`，备份放在 `Backups/`。升级或移动应用不会移动这些资料。

所有普通启动都使用这一份资料，与应用文件名、所在文件夹及正式 / 验证 Bundle ID 无关。第一个实例持有资料目录的进程锁；再次打开会请求它显示面板，随后退出，因此只有一个计时状态和一个写入者。唤出请求会等待接收端确认，覆盖两个应用几乎同时启动、首个界面还未完成初始化的情况。

每次关键操作立即原子保存，运行中约每两秒保存恢复检查点。正常退出保存并暂停，重开后主动继续；系统强制终止时恢复最后成功保存的检查点。读取失败或遇到不支持的数据版本会保留原文件并停止写入。

在“设置 → 数据与隐私”中可以在 Finder 显示资料位置和备份。日常主面板不再显示资料库说明条。当前仅为本地保存；账号、网络同步和排行榜尚未实现。

便签原文保存在 `data.json` 的 `notes[].text`，不是每张一份独立文件。便签列表和桌面便签上的“导出 TXT”会打开系统保存对话框，可选择目录与文件名；导出 UTF-8 原文，保留换行和空白，不额外插入标题或日期。

## 独立验证

自动化及破坏性验证使用显式 `--ui-test`，或 `--data-dir 独立目录`。只有 `--ui-test` 时，默认使用 `TomatoNotes-QA`；守护验证包使用 `TomatoNotes-GuardQA`。测试模式拒绝日常目录及其符号链接；缺失或矛盾的参数直接报错，不会悄悄打开日常资料。

独立资料的面板明确显示“独立测试资料 · 与日常记录分开保存”。详情中的“打开本机共用资料库”会先保存当前资料，再唤出或启动日常实例并正常关闭测试实例。原测试资料留在原位，不自动导入。新版本的这项按钮不会改变已运行旧版本的启动参数；旧实例需正常退出后重新打开。

## 合并已有独立资料

先正常退出使用来源和目标资料的全部实例，确保便签编辑和计时检查点已落盘。使用能读取所有来源数据版本的 `TomatoDataTool`；工具遇到更高版本会拒绝处理，不能用旧版覆盖新版资料。

```bash
swift run --package-path apps/macos TomatoDataTool merge \
  --primary "$HOME/Library/Application Support/TomatoNotes/data.json" \
  --source /绝对路径/旧资料/data.json \
  --destination /绝对路径/新合并目录/data.json
```

工具会对来源和目标目录加锁，先备份来源 JSON 及其关联图片，再按稳定 ID 合并到**新文件**。重复导入相同记录不会翻倍；相同 ID 内容不一致、时长不对账或缺失图片会停止，不猜测覆盖。主资料决定设置和当前计时；其他未结束轮次保留已有时长并结束，不凭空增加专注时间。

核对所有来源的记录 ID、数量、按日专注秒数及关联图片后，保留日常原文件和附件的备份，再将合并文件和关联 `Attachments/` 放入日常资料目录。全程保持应用关闭，完成后普通启动。不要只替换 JSON 而遗漏图片，也不要将合并结果重新写回仍在运行的实例。
