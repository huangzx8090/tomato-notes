# Chrome 专注守护

## 使用方式

这里的白名单就是“这轮允许使用的应用和网页”。默认只在离开勾选内容过久时提醒。

1. 在“专注 → 专注范围”打开选择窗口，填写本轮目标，也可以从今天的待办选择。
2. 在“应用”中直接勾选要用的 App；取消勾选就移出。番茄小记自动允许。
3. 在“Chrome 网页”点“读取网页”，逐项勾选要用的页面。每个网站下的页面直接展开，可按标题或网站搜索；“全选”只作用于搜索结果中当前打开的网页。
4. 点击“开始专注”或“保存选择”后才应用到本轮。关闭窗口或取消不会应用草稿；没有勾选任何内容时可选“仅计时”。

### 更多选项

- **AI 帮我勾选**：展开“更多选项”，可请求推荐当前 App 和普通 Chrome 网页。推荐勾选会同步显示在上方清单，仍由底部确认按钮应用。手动调整会保留屏幕上的选择并取消旧请求，防止已取消项被旧建议重新加回。
- **手动添加 / 常用网页**：支持添加具体页面、添加整个网站，以及保存和导入常用名单。“整个网站”包含子域和后续新开页面；普通清单勾选只添加具体页面。旧整站选择保持兼容，取消其中一页时转成其余当前已允许页面的精确选择，最终确认前不写入本轮。
- **AI 关闭无关页面**：需本轮单独勾选，并配置当前服务商、允许 Chrome 自动化和屏幕读取。启用时底部始终显示“AI 关闭已开启”。
- 提醒时间与每轮上限仍在设置中调整，默认提醒 / 再等待各 60 秒、AI 最多 3 次。
- 可在设置中开启“自动沿用上轮目标与白名单”，默认关闭。新一轮始终不继承 AI 关闭授权；关闭沿用开关会清空保存的名单。

## 调用流程

```text
本轮目标与白名单
       ↓
本机检查前台 App / 当前 Chrome 标签
       ↓ 非白名单持续超时
轻提醒（不消耗 AI）
       ↓ 再等待，仍未返回，且本轮允许 AI 关闭
只截取当前普通 Chrome 窗口
       ↓
DeepSeek 判断学习相关性（单张图片 + 目标 / 网站 / 标题）
       ↓ 明确无关，置信度至少 0.9
重新核对本轮、计时、前台窗口、标签 ID、URL 与标题
       ↓ 全部一致
关闭该标签，并核对该对象已不存在
```

相关或无法确定的页面本轮保留，不反复发给 AI。调用失败也不反复自动请求。返回白名单、切换标签或暂停会重新计算停留；AI 判断期间切换 App / 标签会取消关闭。睡眠或异常长间隔不算作继续离开。AI 次数上限为每轮 1–5 次，编辑或暂时关闭后重新启用同一轮守护，不会重置已消耗次数。

生效白名单只保存在内存并绑定这一轮的 session ID。暂停保留，结束失效；重启后先暂停计时。未开启沿用时，再次开始需重新确认；开启沿用时从本机保存的名单创建本轮计划，始终移除 AI 关闭授权。其他 App 不自动退出。无痕窗口不读取内容、不截图、不关闭；Chrome 内部设置与 file 页面等非 http(s) 页面不发送给 AI 或关闭，无法可靠判断时保留。

## 隐私与 Token

AI 白名单推荐是开始前的独立文字请求：主动点击时读取当前运行的普通 App，以及所有普通 Chrome 窗口的 HTTP(S) 网页。仅发送目标、App 名称、网页标题与网站；真实 App ID、窗口 / 标签 ID、完整 URL 和查询参数留在本机，通过临时 ID 把建议映射回候选。每次重新推荐都会重新读取，不读取浏览历史、不截图、不读取无痕标签。推荐用量单独显示，不计入守护的关闭判断次数。较多候选分批处理，全部成功后才显示可确认的建议；失败或取消时不应用部分结果。详见 [AI 白名单推荐](AI白名单推荐.md)。

正常检查只通过 `NSWorkspace` 与 Chrome 内置 Apple Events 接口读取前台 App、当前窗口 / 标签的标题与 URL；不注入网页脚本，不读取浏览历史。只有用户本轮勾选 AI 关闭后才发送 Chrome 窗口截图，截图不写磁盘，AI 请求不包含 URL 查询参数或完整路径。标题、网站与本轮学习目标会发送给 DeepSeek。

使用现有钥匙串中的 Key 和 `deepseek-flash`，非思考模式、短 JSON 结果、每次最多输出 400 Tokens。界面显示本轮已请求次数与服务端返回的输入 / 输出 Token 用量，失败请求的实际计费以服务商为准。

当前 [DeepSeek 图片文档](https://api-docs.deepseek.com/guides/vision/) 规定每张图片输入上限为 1024 Tokens；每次还包括短提示词、目标与标题。费用依据 [官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，不在客户端写死价格。

## 验证状态

- 47 项自动化测试通过，其中守护测试包括网址域名边界、视频查询参数区分、停留提醒与单次判断、暂停 / 长间隔排除、保守关闭条件、Apple Event 矩形与错误解析、截图窗口唯一匹配、沿用名单不会继承关闭授权，以及图片请求和 Token 用量解析。
- 原生自动化受 ScreenCaptureKit 截图错误影响，按用户要求停止重复实机操作。真实 Chrome 授权、截图与关闭仍待人工确认，构建通过不能替代这条实机链路。详见 [体验优化与验收顺序](体验优化与后续建议.md)。

验证包 `Scripts/build-app.sh release --guard-qa` 使用独立 Bundle ID；运行验证时必须带 `--ui-test`（默认使用 `TomatoNotes-GuardQA`），或显式提供 `--data-dir` 独立目录。普通打开应用包会使用日常共用资料。专用参数 `--guard-check-url` 仅在该验证包且目标为 localhost / 127.0.0.1 时启用；它将守护限制在指定的本地验收页面，其他页面完全不触发守护，并只输出无页面内容的阶段与用量日志。

Chrome 控制接口以本机 `/Applications/Google Chrome.app/Contents/Resources/scripting.sdef` 为依据；单次截屏使用 [Apple SCScreenshotManager](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager)。权限未授权、页面改变或系统截图失败时不会执行关闭。
