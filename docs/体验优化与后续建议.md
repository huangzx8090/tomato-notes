# 使用体验与后续建议

## 本次完成

- 顶部新增独立“待办”，置于专注与今日之间，切换页面回到顶部；暖色纸张清单提供触感勾选、划线、完成时间、进度环与整单完成印章。
- 便签默认显示今天，历史按日期分组；继续使用建立今日副本且保留原稿，重复点击不覆盖补写。删除逐张确认并关闭对应窗口。详见 [便签与待办体验](便签与待办体验.md)。
- 外观提供“跟随系统 / 浅色 / 深色”。深色使用暖棕底色、奶油色文字与胡桃色旋钮；玻璃开关独立保留。主面板、AI 回顾、浮动便签、快速待办和白名单窗口共用外观。
- 白名单使用独立标准窗口，打开时聚焦目标；从菜单栏 / Dock 再次唤出时优先回到正在编辑的白名单，防止主面板抢走输入。
- 可从今天未完成的待办选择学习目标，Chrome 标签支持按标题 / 网站筛选，已加入的页面有明确状态。
- 默认逐轮重新确认名单。“自动沿用上轮目标与白名单”默认关闭；主动开启后，后续开始时自动应用到新一轮。AI 关闭授权不沿用，每轮另行开启。Esc / Command + W 可关闭白名单窗口。
- “本轮仅计时”临时跳过守护，不修改全局开关；暂停后继续保持本轮选择。之后重新开启本轮守护也不会重置已经消耗的 AI 判断次数。
- 提醒中的“本轮放行”绑定提醒时的页面；AI 期间切换 App / 页面会取消关闭。窗口截图必须同时匹配标题、位置和尺寸，不能唯一确定时保留页面。
- 核心改为“进展先出现”：不写复盘也能看到每轮投入与已有成果。开始前目标可选、可从待办点选；守护中的目标自动进入记录，暂停后保留，默认逐轮隔离。
- 每轮自动生成本机进展卡，今日页提供“时间都变成了什么”时间线；只把专注分段内勾选完成的待办归入该轮，暂停与休息时的操作不混入。
- 每轮自动 AI 回顾为可选开关，默认关闭。开启后，新结束且投入至少 1 分钟的轮次在后台尝试一次；不额外弹窗、不要求反思、不自动重试、不补跑历史。文字和图片收在可选补充区。

浅色 / 深色由 [Apple 的应用外观机制](https://developer.apple.com/documentation/appkit/choosing-a-specific-appearance-for-your-macos-app) 统一驱动；跟随系统时不覆盖系统外观，不修改 macOS 的全局设置。

## 核心主线：让投入自然留下进展

“无感”指用户正常学习就能留下记录，想补充时只需一句话或一张图。成就感来自真实积累：为一个目标投入了多久、勾选完成了什么、哪些成果有图片或原话依据。无需每轮填写问卷、打分或确认 AI 才能继续。

| 时机 | 当前实现 | 用户需要做什么 |
| --- | --- | --- |
| 开始 | 自动新建轮次；有目标时一同保存 | 直接开始，或从待办点选一次 |
| 过程中 | 记录实际专注分段与允许的 App 时长，归集期间勾选的待办 | 正常学习，照常使用待办 |
| 结束 | 自动出现进展卡；已开启时在后台进行一次 AI 整理 | 先休息，无需填写 |
| 想展示成果时 | 已有记录继续保留，文字和图片自愿补充 | 留一句话或添加一张成果图 |
| 晚上 | 今日时间线和可选定时日报合并展示积累 | 想看时打开 |

例如，有真实完成待办时可显示：“为『学习二叉树』投入 25 分钟，勾选完成『中序遍历练习』。”只有目标与时长时，只显示“围绕『学习二叉树』投入 25 分钟”，不能写“已掌握二叉树”。这能让进展可信，也避免把记录工具变成新的任务。

## 下一步推荐

以下是功能建议，尚未实现。优先级依据当前代码与个人使用场景判断，不代表市场独占功能。

| 优先级 | 建议 | 具体操作与价值 | 实现与 AI 成本 |
| --- | --- | --- | --- |
| 1 | 可选的学习材料足迹 | 独立授权后，仅在专注中保存普通 Chrome 学习页的标题、网站和停留时间；让 AI 知道接触了哪份课程资料。明确排除无痕、完整 URL 查询参数和持续截图，随时可关闭或删除。 | 中；本机累计，结束时合并进已有的一次总结。当前守护读到的页面不会自动持久化或用于成果总结，此项需另行实现。 |
| 2 | 成果回顾可追溯 | 日报里的每项结果都能点回对应番茄、用户原话与图片。读到“今天完成了什么”时立即知道依据。 | 中；复用现有成果与图片 ID，要求 AI 引用受校验的材料 ID。总结仍沿用原有调用。 |
| 3 | 接着上次做 | 下次打开直接显示已有总结的“待继续”；有需要再补一句停在哪里，不设置必填收尾表单。 | 小到中；复用 nextSteps，不增加读取时的 AI 调用，不把 AI 推测写成已完成事实。 |
| 4 | 周进展花园 | 按主题展示这一周真实投入与有依据的成果；点开一片叶子能回到对应记录，不靠虚构积分或连续打卡制造压力。 | 中；已有本地记录可以直接生成，材料不足时展示投入积累。 |

推荐先做“学习材料足迹”，再做“成果回顾可追溯”。当前 App 时长无法说明具体看了什么；加一个明确边界的可选材料来源，比不断要求用户输入更接近无感。页面停留也不能证明已经学会，因此仍需区分浏览事实、用户成果和 AI 推断。

名单拦截已有成熟产品，例如 [SelfControl 的官方说明](https://github.com/SelfControlApp/selfcontrol/wiki/FAQ) 包含按域名阻断及名单保存。因此，本项目适合继续加强“本轮意图 → 有依据的成果 → 下一次行动”的连贯体验。

## 人工体验仍需确认

54 项规则 / 接口测试与本轮 release 构建已执行。离屏配色、进展卡与便签 / 待办预览使用示例数据，只用于检查布局、配色和文字，不能证明真实 Liquid Glass、系统权限、后台 AI 调度或 Chrome 自动关闭成功。便签 / 待办的人工验收要求见对应说明。

这轮原生自动化在目标输入框处反复遇到 ScreenCaptureKit `-3812`。独立窗口已实际创建，应用未崩溃。按用户要求停止重复实机尝试，保留待人工确认的环节：

1. 在独立白名单窗口输入中文，切到别的 App 后从菜单栏 / Dock 返回，文字和键盘焦点保持正常。
2. 在外观里切换三种模式，检查已打开便签、AI 回顾和白名单窗口，玻璃开关分别检查一次。
3. 首次允许 Chrome 自动化与屏幕录制；普通娱乐演示页应依次提醒、等待、调用 AI，并仅在明确无关时关闭。
4. AI 判断期间切换页面，或临时选择“本轮仅计时”，应停止本轮关闭流程。
5. 不填目标直接完成一轮，应自动出现投入卡；从待办点选目标后完成，目标应保留到历史。暂停期间勾选的任务不应归入本轮。
6. 开启每轮自动 AI 后完成至少 1 分钟的专注，只应后台调用一次；断网失败后不连续重试。关闭开关或未配置 Key 时，仍有本机进展卡。

未授权、AI 出错或无法确认窗口时，预期结果都是保留页面。当前不能以自动化测试通过替代上述实机确认。
