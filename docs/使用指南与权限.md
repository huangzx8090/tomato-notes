# 使用指南与权限

本文面向 v1.3.1。系统设置的中文名称可能随 macOS 版本变化；以系统实际提示为准。

## 1. 首次安装与升级

1. 从本仓库的 GitHub Release 下载 DMG 或 ZIP；Universal 包包含 arm64 与 x86_64 两种架构。
2. 将“番茄小记.app”放入 `/Applications`（“应用程序”）再启动，避免一直从 DMG、Downloads 或多个不同路径运行。
3. 升级前在设置中点“备份数据”，正常退出旧版后替换。构建或覆盖文件不会让仍在运行的旧进程自动变成新版。
4. 默认从菜单栏打开，设置可以开启 Dock 图标。Esc 收起面板，计时继续；退出应用会停止计时，重新启动后需主动继续。

### 安装包与首次打开

当前使用 ad-hoc 签名，没有 Apple Developer ID 签名和公证。签名完整性验证通过不等于 Gatekeeper 信任，也不等于 Apple 公证。

如果系统提示无法验证开发者或阻止首次打开：

- 确认来自本项目的 Release，核对附件校验值。
- 尝试打开一次，再查看 **系统设置 → 隐私与安全性** 中针对该应用的提示；确认来源可信后按提示选择“仍要打开”。
- 参照 [Apple 官方说明](https://support.apple.com/zh-cn/102445)，单位管理设备可能限制此操作。

无需关闭系统 Gatekeeper 或 SIP。若系统明确提示恶意软件或文件损坏，请停止安装并重新核对来源及下载完整性。

将 `SHA256SUMS.txt` 和对应版本的附件下载到同一目录，终端中进入该目录后可校验：

```bash
shasum -a 256 -c SHA256SUMS.txt
```

该清单同时列出 DMG、ZIP 与安装说明；只下载一个安装包时，其他文件显示缺少不代表已下载的文件校验失败，请看对应文件的结果。更简单的方式是 `shasum -a 256 文件名`，与清单中该文件的一行逐字对比。

## 2. 哪些权限需要开启

只启用自己使用的功能即可。

| 使用场景 | 权限 / 入口 | 未授权时 |
| --- | --- | --- |
| 番茄钟、待办、浮动便签、每轮本机进展卡 | 无额外隐私权限 | 正常使用 |
| 记录前台 App 名称与停留时长 | 应用内“前台 App 记录”开关，不需屏幕录制 | 开关关闭后对应时间归入“未记录” |
| 阶段结束等系统通知 | 系统设置 → 通知 → 番茄小记 | 记录和计时保留，无系统横幅 |
| Chrome 当前窗口标签选择、页面白名单和守护 | 系统设置 → 隐私与安全性 → 自动化 → 番茄小记 → Google Chrome | 无法读取和控制 Chrome 标签 |
| 本轮允许 AI 核对后关闭标签 | 隐私与安全性 → 屏幕录制，或屏幕与系统音频录制 | 无截图，不执行 AI 自动关闭 |
| 保存 / 读取 DeepSeek Key | macOS 钥匙串可能询问 | 读取失败时 AI 不可用，本地功能继续 |
| 主动选择成果图片 | 系统文件选择器；文件所在位置须可访问 | 不能导入选中的文件 |

**不需要辅助功能、输入监控、完全磁盘访问、摄像头或麦克风权限。** 不读取键盘输入、剪贴板历史或照片图库，不需要授予照片权限。上传图片是用户从文件选择器主动选择，不会扫描相册。

### 通知

- 首次开始或在设置中点“通知权限 / 测试提醒”时，按系统提示允许。
- 在 **系统设置 → 通知 → 番茄小记** 调整横幅等呈现方式，另检查系统“专注模式 / 勿扰”。
- “一次提示音”是应用内独立选项；关闭系统通知不等同于关闭这个声音开关。
- 允许通知不保证每种系统状态都出现横幅，实际呈现仍由 macOS 控制。

### Chrome 自动化

1. 打开 **Google Chrome 的普通窗口**，不要使用无痕窗口做首次连接。
2. 在 **专注 → 专注守护** 点“连接 Chrome”，允许番茄小记控制 Google Chrome。
3. 若之前拒绝，在 **隐私与安全性 → 自动化** 中找到番茄小记，开启 Google Chrome；回到应用重新连接。
4. 系统列表通常在应用尝试请求后才出现；没有列表项时，先在应用内触发连接。

通过 Chrome 内置 Apple Events 接口读取当前窗口标签的标题、URL 与标识，不读取浏览历史，不向网页注入脚本。**无需 Chrome 扩展，也无需打开 Chrome 的“允许来自 Apple 事件的 JavaScript”。** 当前只支持 `com.google.Chrome`，不把 Edge、Safari 或其他 Chrome 变体视作已支持。

### 屏幕录制

1. 先配置 DeepSeek Key 和 Chrome 自动化。
2. 在本轮守护中勾选 **允许 AI 确认后关闭无关 Chrome 标签页**，点 **允许关闭前读取 Chrome 窗口**。
3. 按系统提示在隐私设置中开启番茄小记的屏幕录制；系统要求退出重新打开时，请先保存并正常退出再打开。
4. 返回应用点“刷新权限”，重新为当前轮次确认守护设置。

该权限只用于关闭前的最后核对。请求截图时选择当前普通 Chrome 窗口，不持续录屏、不采集系统音频，截图在内存中处理，不写本地文件。**窗口截图可能包含工具栏、其他标签标题及窗口内可见的私人资料**，不是仅裁切网页正文；请在本轮允许前确认可接受这一范围。

授权本身不保证截图成功；多窗口匹配不唯一、系统捕获失败或权限状态异常时会保留页面。只需要本机提醒时不用开启屏幕录制。

### 钥匙串与升级后的权限

填写 Key 后保存在本机钥匙串。读取时若 macOS 询问，请核对应用名称和安装来源；应用不会要求把钥匙串密码填写进自身界面。

当前包没有稳定的 Developer ID 身份。替换版本、切换正式 / 验证包或改变路径后，系统可能重新询问自动化、截图或钥匙串权限；旧授权是否继续有效以系统当前状态为准。优先固定从“应用程序”启动，按上述入口重新连接或授权。

## 3. AI：什么时候发送什么

AI 接口固定为 `https://api.deepseek.com`，模型为 `deepseek-flash`。基础功能无需 Key；AI 功能需要用户自己的 DeepSeek API 额度，费用按 [官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 计算。

| 触发方式 | 发送的内容 | 自动行为 |
| --- | --- | --- |
| 测试连接 | API 鉴权并请求模型列表，无总结材料 | 不生成成果，不证明图文总结链路已通过 |
| 本轮 / 当天手动总结 | 选定范围的目标、投入、App 名称与时长、待办、描述和关联成果图片 | 用户点击后执行 |
| 结束后自动总结 | 新结束且投入至少 60 秒的轮次材料 | 默认关闭；每轮仅自动尝试一次，不扫描历史，失败不反复重试 |
| 每日定时回顾 | 当天材料与各轮已有总结；必要时先解析未总结或已修改轮次的图片和描述 | 默认关闭；每天一次定时尝试，可能包含多个请求 |
| 守护最后核对 | 本轮目标、网站、当前标题及当前 Chrome 窗口截图 | 必须本轮另行授权，提醒并再等待后才调用 |

- 只写目标、编辑描述、导入图片或勾选待办，不会立即发起 AI 总结。
- 自动每轮总结与定时日报互相独立。关闭一项不代表另一项也关闭；关闭自动选项不撤回已经发出的请求，也不删除现有结果。
- 成果图片导入后留在本机 `Attachments/`；最多 6 张，每张原文件最多 25 MB，导入时转为最长边 1600 像素内的 JPEG。原始文件不被修改；上传的是处理后的副本。
- 守护截图不转为成果附件、不落盘；发送元数据时不带完整 URL 路径和查询参数，但图片和标题自身仍可能含敏感信息。
- 本地不保存截图不代表服务商不会处理或留存请求。服务端政策由 DeepSeek 决定，敏感材料请先裁剪或遮挡，再主动选图。
- 自动生成失败不覆盖已有总结。手动重新生成会再次消耗额度；多轮日报的次数通常超过一次。
- 守护默认每轮最多 3 次判断，可设置 1–5 次；达到上限后只提醒。界面用量来自服务端返回，失败请求的计费以服务商为准。
- AI 内容可能不准确。App 时长不证明任务完成或知识掌握；图片中的可见成果也需要本人核对。

### Key 配置与错误排查

优先使用应用设置保存 Key。支持进程环境变量 `deepseek` 或 `DEEPSEEK_API_KEY`，顺序为 `deepseek` → `DEEPSEEK_API_KEY` → 钥匙串；环境变量存在时，在界面更换或移除钥匙串 Key 不会覆盖环境变量。终端 `export` 通常不影响 Dock 启动的应用。

开发者可在已配置变量的同一个终端导入钥匙串，命令不会输出密钥：

```bash
swift run TomatoDataTool import-deepseek-key
```

| 现象 | 检查方式 |
| --- | --- |
| 未配置 Key / 鉴权失败（401） | 重新保存有效 Key；确认启动环境没有旧变量覆盖 |
| 权限不足、额度或限流（403 / 429） | 查看服务商账号、额度和限制；不要连续重复点击 |
| 网络 / 超时 / 服务错误 | 核对网络能访问 DeepSeek，稍后手动重试；旧记录和旧总结保留 |
| 测试连接成功但总结失败 | 连接测试只验证模型接口；继续核对服务额度、模型、图片与错误提示 |
| 图片导入失败 | 核对格式、原文件大小、数量和文件访问权；HEIC 会先在本机转成 JPEG |

## 4. 白名单与自动关闭的边界

- 白名单默认只对本次专注有效，暂停保留、结束失效。重启后的活跃计划不作为自动关闭授权恢复。
- 可选“自动沿用上轮目标与白名单”，默认关闭。开启后名单会保存并用于新一轮；关闭开关清空保存名单。**AI 关闭授权始终不沿用**。
- Chrome 用页面规则判断，其他 App 用 App 规则判断；番茄小记自动放行以方便待办和便签操作。
- “此页”保留查询参数，适合同一视频网站中的具体课程；“网站”覆盖该域名与子域名，会同时放行这个网站里的其他内容。
- 默认离开白名单 60 秒提醒，再等待 60 秒才可能 AI 核对；最短分别为 5 秒。切换 App / 标签、返回白名单或暂停会重新计算停留。
- AI 只有明确判为无关且置信度至少 0.9 才可能关闭；关闭前重新确认轮次、运行状态、前台窗口、标签 ID、URL 与标题。
- 其他 App 只提醒，不会强制退出。无痕窗口不读取内容、不截图、不关闭；Chrome 内部页及非 HTTP(S) 页不执行 AI 关闭。
- 无法判断、页面已变、权限不足、网络或截图失败时保留标签。同一页不反复请求，编辑本轮守护也不重置已消耗次数。
- 误关可尝试 Chrome 的 **Command + Shift + T**，但未提交表单或页面临时状态可能无法恢复。重要编辑页不宜作为首次测试对象。

## 5. 记录、日期与定时

- 记录前台 App 仅在专注运行时生效；暂停、休息和退出不计入。只记录 App 名称与时长，不据此读取文档内容。
- 本地日期以运行电脑当前时区为准；跨日会拆分统计。更改时区或系统日期可能改变“今天”显示范围，历史并未因此删除。
- 锁屏、系统睡眠、重启后暂停，返回后需主动继续。合盖外接活动屏幕时的继续计时受设置与系统实际睡眠状态共同影响。
- 阶段结束不会自动进入下一阶段，避免离开电脑后一直增加番茄轮数。改时长不会重置正在进行的阶段。
- 每日定时回顾需要应用运行且解锁；应用不能在退出或系统睡眠时唤醒自己。当天错过时间后会补尝试；完成一次定时尝试后不再自动重复，失败可手动重试。
- 程序退出时未发出的自动每轮回顾队列不会下次补跑；定时日报可以按当天资料再整理。

## 6. 待办与便签

- 待办属于创建当天，不自动移到下一天；历史在“今日”按日期查看，历史清单只读。
- 勾选可撤回完成，双击改字；删除用垃圾桶或右键。底部“撤销”按删除逆序恢复原记录，关闭提示或退出后本次撤销记录清空。
- 便签默认今天；“历史便签 → 继续使用”建立今日副本并保留原稿。同一天重复继续只打开已有副本，不覆盖补写。
- 收起便签窗口会保留资料，删除便签经过确认后不能在应用内撤销。重要内容先备份。
- 只有专注运行时完成的待办才归入该轮进展；目标、暂停中完成的任务或 App 时长不会被自动冒充为具体成果。

## 7. 备份、恢复与卸载

正式资料目录：`~/Library/Application Support/TomatoNotes/`。开发验证包默认使用独立目录；不要把空的验证资料当成正式资料丢失。

### 备份

使用 **设置 → 备份数据**，保留生成的 JSON 和同名 `.assets/Attachments/` 文件夹。图片缺少时，文字可能仍能恢复，原图总结却无法完整重建。备份不包含钥匙串 Key，不等同于跨设备同步。

### 手动恢复

当前没有一键恢复向导。谨慎按以下顺序操作：

1. 正常退出所有使用这份资料的番茄小记实例。
2. 先把整个现有 `TomatoNotes` 资料目录复制到另一个位置留底。
3. 将选定备份 JSON 复制为正式目录的 `data.json`；将该备份同名 `.assets/Attachments/` 的内容恢复至正式目录的 `Attachments/`。
4. 重新打开应用并核对计时记录、待办、便签和图片；必要时在设置中重新配置 Key。

不要在应用运行时编辑 JSON，也不要只用旧 JSON 配上不匹配的附件。数据结构旧版本升级前会备份；**新版资料不保证可以无损降级给旧应用**。

### 卸载与隐私

删除应用包不会自动删除资料和钥匙串 Key。若要彻底移除，先备份，再自行清理资料目录，并在应用设置移除 Key 或在“钥匙串访问”中管理 `com.zixuan.TomatoNotes.deepseek` 项。若曾设置环境变量，还需移除对应启动环境配置。撤销权限可在系统隐私设置完成。清理前确认不再需要历史与图片。

## 8. 常见问题

| 问题 | 建议 |
| --- | --- |
| 打开后看不到窗口 | 看屏幕顶部菜单栏；可开启 Dock 图标。相同资料目录重复启动会唤出已有实例 |
| 升级后看起来还是旧版 | 正常退出旧进程，再从“应用程序”打开替换后的版本，设置底部核对版本号 |
| 通知不弹出 | 同时检查应用通知开关、系统通知与专注模式，用“测试提醒”检查 |
| Chrome 标签列表为空 | 确认普通 Chrome 窗口正在运行，连接并检查自动化权限；当前窗口最多列出 60 个标签 |
| 白名单明明保存了却不能用 | 区分本轮与沿用设置，检查是否新一轮、暂停或重启，以及 URL 查询参数是否变化 |
| 不能截图或自动关闭 | 检查本轮授权、目标、Key、两项权限、等待时间和每轮次数；系统截图失败时预期保留页面 |
| 计时突然暂停 | 核对锁屏、睡眠、合盖 / 外接屏策略；恢复后需要手动继续 |
| 快捷键无反应 | 在设置换键，检查第三方占用；不用为此额外开启辅助功能或输入监控 |
| 玻璃或动画没有显示 | 检查玻璃开关、系统版本、减少透明度 / 动态效果设置；暖纸背景保持不透明 |
| 资料只读或保存失败 | 先保留原始目录和错误提示，检查磁盘空间及同库实例；不要删除资料来“重置” |

## 9. 已知验证范围

本次发布有 58 项规则与接口测试、Universal 构建、签名、归档和校验值检查。AI 接口测试使用模拟响应，不消耗真实 Key。

这些检查不替代真实系统通知、Chrome 权限 / 截图 / 自动关闭、多屏全屏、玻璃流动与触感。此前原生捕获工具出现系统错误，按用户要求已停止重复实机测试，**本次发布的 Chrome 截图与自动关闭仍未完成端到端人工验收**。支持范围声明与实际机器验收请分开理解；界面成功启动或规则通过都不代表上述链路已完成。
