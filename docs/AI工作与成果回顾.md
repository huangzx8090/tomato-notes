# AI 工作与成果回顾

当前开发分支新增可选的 [AI 自动记录](AI自动记录.md)，自动采集授权材料并识别主题，使用 v4 资料格式。下文保留原回顾功能的设计与历史验证；新增流程的实际边界与验收见新文档。

## 本次需求

- 每轮番茄钟由 AI 总结做了什么、取得了什么成果。
- 支持补充文字，描述不清时可添加图片供 AI 理解。
- 用户设定每天一个时间点，由 AI 汇总当天所有工作与成果。
- 第一家接入 DeepSeek，用户配置 API Key 即可使用。
- 计时参数改为可拖动、可精确微调的仿真旋钮。
- 主面板和成果窗口保留温暖的纸感背景，仅按钮与顶部四项切换栏使用玻璃效果。
- 设置提供“按钮玻璃效果”开关，立即生效并保存；页面选择使用类似 App Store 底栏的流动玻璃胶囊。

## 实现

### 无需每轮填写的进展记录

开始时可以直接计时，也可从待办点选或填写本轮目标；守护中填写的目标同步保留。目标随轮次保存，暂停恢复不丢失，默认不带到下一轮。每轮进展卡直接从实际计时分段、目标和专注期间勾选完成的待办生成，不依赖 AI。今日页按轮次显示进展，提前结束的实际投入同样保留。

“专注结束后自动整理 AI 回顾”默认关闭，与定时日报分别保存。主动开启且已配置 Key 后，新结束并投入至少 60 秒的轮次加入本次运行的后台队列；解锁且没有其他生成任务时执行。先持久化尝试标记，再发送本轮材料；每轮只自动尝试一次，失败不自动重试，不扫描过去的轮次。手动生成仍可重试，定时日报仍按自身设置整理材料。退出前尚未发出的排队请求不在下次启动补跑。

自动 AI 回顾仅发送已有目标、计时、App 名称与时长、完成待办，以及该轮主动补充的文字和图片；不会自动截图，也不把守护临时截图转成成果材料。用户可展开“补充一句或图片（可选）”，不用每轮写反思。

目标只能说明计划，前台 App 时长只能说明投入。材料不足时，AI 可以写围绕某目标投入多久，成果数组必须为空；不评分、不凭时间推断学会、不把提前结束写成失败。具体成果仍需要用户勾选待办、原话或图片证据。

### AI 材料与保存

成果以稳定 ID 关联专注轮次或本地日期，保存文字、图片引用与 AI 结果。AI 结果包含工作、成果、后续事项和待确认信息，并记录模型、生成时间和输入摘要。修改文字、图片或计时数据后，界面提示可以重新生成。

日报生成分两步：先为当天尚未总结或已经修改的各轮记录生成成果总结，再结合这些总结、原始描述、当天待办和 App 投入情况生成全天报告。各轮图片不会每次重复上传，新增或修改材料会触发重新理解。用户也可给当天补充文字和图片。

提示词明确要求把用户描述、图片可见证据和不确定信息区分开；禁止从 App 时长推断已完成具体任务。图片文字和资料中的指令只作为资料分析，不改变系统任务。AI 结果仍需用户核对。

API Key 仅存在本机钥匙串或当前进程环境，固定发送至 `https://api.deepseek.com`。请求不跟随重定向，不回显原始错误响应或密钥。使用 `deepseek-flash`、非思考模式和 JSON 结果格式；该模型的文字与图片能力依据本次查阅的官方文档。

定时以当前本地日期和设定小时、分钟为准，约 15 秒检查一次。应用运行、未锁屏且已到时间时开始；错过当天时间会补执行。一次定时尝试结束后持久化日期以防重复；失败原因可在重启后继续查看。中途退出没有标为已完成，重启后可补执行。

图片导入复制到本机附件目录，限制数量与大小、校正方向并缩小为 JPEG。备份同时复制关联图片。数据 v1 升级前保留原始字节，v2 增加成果资料与定时状态。

外观设置 `glassControlsEnabled` 随原有设置保存在本机；旧资料缺少该字段时默认开启。该开关通过 SwiftUI Environment 同时影响主面板与所有已打开的成果窗口，切换时无需重建窗口。窗口背景和纸感卡片始终不透明。顶部导航使用单个持续存在的胶囊形状，通过可动画位置连续移动；途中轻微拉长、到位后收圆，再将原生 Liquid Glass 应用到该形状。文字与图标放在整个玻璃容器外的上层，避免被玻璃采样而模糊。关闭玻璃或旧系统时保留纸感 / 材质与滑动过渡。系统要求减少透明度时使用纸感；减少动态效果时停用流动动画。

## 验证

- 当前共 47 项规则与接口测试通过。新增 8 项进展测试验证无需手工记录仍能生成进展、目标逐轮隔离与暂停恢复、暂停任务排除、跨日边界、旧设置兼容、自动生成门槛、尝试标记持久化及过期总结不再当作日报依据。
- 新进展界面与每轮后台调度已通过编译和 release 构建；尚未重新完成真实界面和 DeepSeek 后台整轮调用验收。下列实机记录为此前文字 / 图片 / 日报版本的验证，不能替代新增流程的验证。
- 本轮已实机完成文字输入、图片选择导入、缩略图、自动保存、未配置密钥时的错误保护。
- 用户配置密钥后，已观察到真实 `deepseek-flash` 返回并保存本轮文字与图片总结；结果正确指出验收图未显示登录页面，没有把描述直接当成图片证实的成果。
- 已实机生成并保存当天的真实 DeepSeek 汇总；在验证目录开启已过时间的定时设置后，自动补生成成功并持久化当日去重标记，随后还原为原先的关闭状态。
- 已逐一点击四个页面，确认选中状态和清晰标签；验证包的导航帧日志记录到连续中间位置和胶囊拉伸，开关关闭 / 开启与磁盘保存均已核对。
- 系统锁屏、睡眠、全屏便签等旧版实机待验项仍见早期收尾评估；不能以规则测试替代全部硬件环境验收。

## 技术依据

- [DeepSeek 首次调用](https://api-docs.deepseek.com/zh-cn/)：默认接口、当前模型名称与鉴权方式。
- [DeepSeek 模型说明](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)：`deepseek-flash` 支持图片理解，`deepseek-v4-pro` 当前不支持图片。
- [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)：文字/图片内容、JSON 格式、完成状态及非思考模式。
- [Apple 自定义 Liquid Glass](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views)：按钮使用 `glassEffect`，导航胶囊在 `GlassEffectContainer` 内应用该材质。实际 API 可用性同时核对本机 macOS SDK 接口。
