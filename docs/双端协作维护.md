# 双端协作维护

番茄小记是一个仓库、两个原生客户端：macOS（Swift / SwiftUI）与 Windows（C# / WPF）。它们共享资料契约和发布流程，不共享 UI 代码。

## 目录职责

| 路径 | 主要维护人 | 内容 |
| --- | --- | --- |
| `Sources/`、`Tests/`（macOS Swift 测试） | macOS 维护者 | macOS 应用、核心规则、系统接口 |
| `Packaging/`、`Scripts/build-app.sh`、`Scripts/package-release.sh` | macOS 维护者 | macOS 应用包与发布产物 |
| `Windows/` | Windows 维护者 | WPF 客户端、Windows 测试、Inno Setup 安装器 |
| `Windows/Packaging/` | Windows 维护者 | Windows 安装脚本、中文语言资源、安装说明 |
| `Compatibility/` | **双方共同评审** | v4 资料契约样例；任何修改都需要两端知情 |
| `Package.swift`、`Scripts/test.sh` | macOS 维护者 | SwiftPM 配置与 macOS 规则测试 |
| `Scripts/package-windows.ps1` | Windows 维护者 | Windows 发布打包 |
| `Scripts/validate-release.sh`、`.github/workflows/` | **双方共同评审** | 版本校验、CI、Release 双端产物 |
| `README.md`、`CHANGELOG.md`、`docs/releases/` | **双方共同维护** | 用户文档与发布记录 |
| `AGENTS.md`、`CONTRIBUTING.md` | **双方共同维护** | 分支与协作约定 |

“主要维护人”不是排他权限：任何人都可以跨端提交修复，但涉及另一端核心行为、资料格式或发布流程时，PR 需要该端维护者评审。

## 代码所有者

GitHub CODEOWNERS 可在 PR 上自动请求指定评审人。仓库目前未配置 `.github/CODEOWNERS`，因为缺少 Windows 维护者的实际 GitHub 用户名，不能写入占位账号。

确定用户名后，将 `CODEOWNERS.template` 复制为 `.github/CODEOWNERS` 并替换 `@WINDOWS_MAINTAINER`：

```bash
cp .github/CODEOWNERS.template .github/CODEOWNERS
# 编辑其中的 @WINDOWS_MAINTAINER 为同伴的实际 GitHub 用户名
```

说明：

- CODEOWNERS 只对**已配置分支保护**的分支强制评审。当前私有仓库无法启用服务端分支保护（见 [CONTRIBUTING](../CONTRIBUTING.md)），因此它只是自动请求评审，不是强制门禁。
- macOS 维护者的用户名写在模板中后同样生效；如后续有多人维护同一端，可以在同一行追加多个用户。

## 工作流约定

### 功能与修复

```text
main ── 发布 PR ← develop ← feat|fix/xxx（来自任一端）
```

- 从最新 `origin/develop` 建短分支，命名用 `<类型>/<英文描述>`，不加个人名前缀。
- 只改本次范围内的文件；不要顺手改另一端目录。
- 跨端变更（资料格式、版本号、CI、发布流程）必须让另一端维护者知情并评审。
- CI 会同时跑 macOS 与 Windows 测试；改到打包输入时两端安装包都会验证。

### 发布

发布时两端版本号必须一致，由 `Scripts/validate-release.sh` 强制检查：

- `Packaging/Info.plist`（macOS）
- `Windows/TomatoNotes/TomatoNotes.csproj`（Windows）

两端都构建成功后，Release 才会公开。Windows 构建失败时不会发布只有 macOS 附件的版本，反之亦然。具体见 [发布流程](发布流程.md)。

### 资料契约

- 任何资料格式变更都以 `Compatibility/data-contract-v4.json` 为共同回归样例，两端测试都要通过。
- 新增字段时更新契约样例和两端解析；未知字段必须保留。
- schema 升级需要迁移与备份策略，不能只改一端。
- 两端不自动同步数据；密钥（Keychain / DPAPI）不跨端迁移。

## 沟通与交接

- PR 描述中写明影响的平台：`macOS`、`Windows` 或 `双端`。
- 涉及用户可见行为的变化，同步更新 `README.md` 和对应平台的安装说明。
- 一端发现另一端的问题，优先开 issue 或在 PR 中说明，不直接大改另一端不熟悉的代码。
- CI 失败时由提交方的维护者先排查；打包或 Release 工作流问题由双方共同处理。
